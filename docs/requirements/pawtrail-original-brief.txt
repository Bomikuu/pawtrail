# PAWTRAIL — FULL APPLICATION IMPLEMENTATION PROMPT

## 1. Project Overview

Build a complete, modern, responsive web application called **PawTrail**.

**Tagline:** Every Paw Has a Story.

**Secondary tagline:** Discover. Care. Connect.

PawTrail is a community-powered animal welfare platform that combines animal discovery, location-based assistance, pet adoption, community fundraising, gamification, and social interaction.

The platform should feel like a combination of:

- **Google Maps:** Discover animals and animal welfare activities around you.
- **Tinder:** Swipe through adoptable animals and find a compatible companion.
- **GoFundMe / Kickstarter:** Raise money for animal operations, food, rescue expenses, and shelter needs.
- **Petfinder:** Explore adoptable animals and detailed animal profiles.
- **Social Media:** Share sightings, rescue stories, feeding activities, and animal updates.
- **Gamified Community Platform:** Earn Kibble for helping animals and compete on the Top PawPal leaderboard.

Despite supporting multiple features, PawTrail must maintain a unified experience focused on helping animals.

**Core philosophy:**

Every animal has a story, every location matters, and every act of kindness should make a difference.

# 2. Technology Stack

Use the following technologies.

### Frontend

- Next.js with App Router
- TypeScript
- React
- Tailwind CSS
- shadcn/ui
- Lucide React for icons
- Google Maps JavaScript API
- `@vis.gl/react-google-maps` for React map integration
- TanStack Query for API data fetching and caching
- Zustand for lightweight client-side state
- React Hook Form with Zod validation
- Framer Motion or Motion for animations
- Recharts for dashboards and analytics

### Backend

The actual backend will use:

- Django
- Django REST Framework
- GeoDjango
- PostgreSQL
- PostGIS
- JWT authentication
- Docker containers for deployment

For this implementation, focus on the **Next.js frontend**.

Build a complete application using realistic mock data and a centralized API service layer.

The application should be designed so mock implementations can later be replaced with Django REST Framework endpoints without rebuilding the frontend.

Use TypeScript interfaces and domain-specific API modules.

### Development requirements

- Use functional React components.
- Prefer Server Components whenever appropriate.
- Use Client Components only where interactivity is required.
- Follow Next.js App Router conventions.
- Use Tailwind for styling.
- Use shadcn/ui as the primary component system.
- Do not use semicolons in frontend TypeScript or JavaScript.
- Keep code consistently formatted.
- Create reusable components.
- Implement loading, empty, and error states.
- Do not leave broken buttons or nonfunctional interactions.
- Avoid excessive dependencies and unnecessary abstractions.

# 3. Branding and Visual Identity

The application should use a playful but professional visual identity.

## Logo Direction

Use the established PawTrail logo concept:

- Cute orange-and-white cat.
- Cute cream-and-brown dog.
- Orange map location marker containing a paw.
- Rounded, hand-drawn illustration style.
- Flat 2D artwork with thick, friendly outlines.

The design should resemble a modern community application rather than a corporate veterinary management dashboard.

## Color Palette

Use a warm, friendly palette.

| Purpose | Color | Hex |
|---|---|---|
| Primary | Warm Orange | `#F97316` |
| Primary Dark | Deep Orange | `#EA580C` |
| Secondary | Forest Teal | `#0F766E` |
| Accent | Soft Green | `#84CC16` |
| Background | Warm Cream | `#FFFBF5` |
| Card Background | White | `#FFFFFF` |
| Primary Text | Dark Brown | `#3B2416` |
| Muted Text | Warm Gray | `#78716C` |
| Border | Light Beige | `#EDE5D8` |

Use orange for primary actions and important highlights.

Use teal or green for positive community actions, verified statuses, and welfare-related information.

## Typography

Use a friendly rounded typeface for headings, such as Nunito.

Use a highly readable typeface for body text, such as Inter.

## Design Rules

1. Use a clean, modern layout.
2. Keep generous spacing between sections.
3. Use rounded cards and buttons.
4. Use subtle borders and very light shadows.
5. Avoid glossy elements and heavy gradients.
6. Avoid excessive decorative elements.
7. Use flat doodle-style animal illustrations.
8. Add meaningful hover states.
9. Support light mode first.
10. Ensure the application works well on mobile devices.

The design should be visually engaging without becoming childish.

### Doodle Illustration Style

Use a consistent illustration system:

- Flat colors.
- Thick rounded outlines.
- Simple facial expressions.
- Minimal shading.
- Orange, brown, cream, teal, and green accents.
- Cute cats, dogs, paw prints, trails, and map markers.

Use illustrations primarily for landing pages, onboarding, and empty states.

Use real animal photographs for listings, profiles, adoption cards, and fundraising campaigns.

## Example Adoption Card

Female · 8 months  
Mixed Breed  
Davao City

Playful · Friendly · Loves Attention

Buttons:

❌ Pass  
❤️ Interested  
👁 View Profile

## Matching Logic

When a user marks an animal as Interested:

1. Save the animal to the user's interested list.
2. Allow the user to review its full profile.
3. Allow the user to submit an adoption application.
4. Notify the responsible shelter or rescuer.
5. The shelter reviews the application.
6. If approved, PawTrail enables the next adoption steps.

**Swiping right does not automatically approve adoption.**

An adoption match means the user has expressed interest and may be compatible—not that an adoption has been finalized.

## Adoption Preferences

Before starting, users can optionally answer a questionnaire.

Questions include:

- Preferred animal species.
- Preferred age range.
- Preferred animal size.
- Living environment.
- Experience with animals.
- Other pets at home.
- Activity level.
- Preferred personality.
- Maximum travel distance.

## Compatibility Recommendations

Use a simple rule-based compatibility system initially.

Do not require AI.

For example:

```text
Compatibility Score:

Species Preference          20%
Living Environment          20%
Lifestyle Compatibility     20%
Experience                  15%
Other Pets Compatibility    15%
Distance Preference         10%
```

These are illustrative weights, not validated animal welfare criteria.

The platform should show explanations such as:

**Good Match — 87%**

"Your active lifestyle and experience with dogs may suit Luna's playful personality."

Avoid presenting compatibility as a guarantee.
