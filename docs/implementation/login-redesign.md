# Login reference adaptation

The 6 November 2026 owner request replaces the plain login form with the supplied reference composition and asks for quieter styling and Google login. The active source remains in the implementation worktree documented by the selected workspace README.

The login route now pairs a restrained community introduction with a white sign-in card on a cream canvas. The second supplied image is served locally as `login-companions.webp`; its alpha is preserved. The form leads on mobile, with a smaller illustration below. Existing light/dark theme support, validated local return paths, demo personas, email errors, session cache isolation and registration behavior remain available. Password visibility is keyboard accessible. The recovery disclosure explains the current reset limitation instead of linking to a nonexistent reset route.

The card, inputs, action controls and loading controls compose the official shadcn components already installed through CLI 4.23.0, as recorded in [the migration provenance](shadcn-tailwind-migration.md). No registry source modifications or new primitive implementations were needed. Ordinary styling uses Tailwind utilities; no stylesheet was added.

Google uses the [Google Identity Services popup authorization-code flow](https://developers.google.com/identity/oauth2/web/guides/use-code-model). The frontend asks only for `openid email profile`, sends the one-time code through the same-origin BFF, then uses the existing encrypted application-session path. The [Google API reference](https://developers.google.com/identity/oauth2/web/reference/js-reference) defines the account picker and popup-error callbacks used here. Missing client configuration, demo mode, blocked scripts, blocked popups, cancellation and backend errors have explicit feedback. The SDK is loaded only on the login route when real mode and a client ID are present. Live use requires the backend endpoint and configuration described in [the integration guide](../backend-integration.md#google-sign-in).

Only source review was performed. No automated tests, type/UI/format/detector checks, production builds, browser verification or delegated reviews were run, per the current project instruction. The development preview was not restarted. No real Google account or credentials were used, and live Google sign-in is not claimed verified.
