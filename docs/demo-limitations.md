# Demonstration boundaries

- All sample people, animal care activity, events, rewards, verification and financial support are illustrative. No actual adoption, rescue, diagnosis, accreditation, donation or payout is performed.
- The filesystem store requires one Node process and private writable disk. It is not a multi-worker or stateless production database. Each browser cookie has a separate overlay; sample personas in that overlay are perspectives for trying a workflow, not independent authenticated users.
- Demo login does not validate passwords. Real mode requires the external Django backend and the documented session contract.
- Exact sighting coordinates, application answers, drafts and receipt/evidence IDs are private. Public animal positions are approximate. Intentionally public event venues are labeled separately.
- Photos remain private until publication review. Evidence and receipts never become public images. Verification never happens automatically from metadata or a role. Demo verification stays explicitly illustrative.
- The demo clock is fixed at 2026-11-02 00:00 Asia/Manila. Sample dates are not real schedules. Kibble is non-cash; no purchase or withdrawal interface exists.
- Licensed photographs, fonts and generated illustration provenance are listed in `docs/assets/credits.md`. The original brand illustration still needs the owner's artistic approval. Missing real animal photographs use honest fallbacks.
- Google Maps requires a browser-restricted key. Lists work without it. The Django adapter requires an actual matching backend. Neither external integration has been live-verified during native implementation.
- New implementation was completed directly, without subagents. No automated tests, type/UI checks, detector runs, builds or browser inspections were executed after the user's testing stop. Source formatting and source review are not runtime or visual verification.
